# Small Worlds 重构实施计划

> 状态：待批准、待实施；本文仅为计划，不证明工具已安装、基线已采集或测试已通过。依据 `docs/small-worlds-refactoring-design.md` 与当前源码。范围是维持原生 Canvas 的视觉及交互兼容，不换引擎、不修原有缺陷、不增加多实例或并发承诺。

## 0. 现状、门禁和依赖

- `src/main.ts` 启动时立即调用 `startApp`，时间、事件和 `draw` 均在闭包内；`src/renderer.ts` 约 2092 行且顶部 `@ts-nocheck`，从低层工具到五个场景集中在一起。`main.ts` 从 `./renderer` 导入，画面通过 `putImageData` 提交后才更新 DOM 背景。
- `package.json` 仅有 Vite、TypeScript 开发依赖和 `dev/build/preview/typecheck`；没有测试框架、自动化浏览器或测试脚本。`tsconfig.json` 开启 `strict`，但只包含 `src`；现有 typecheck 不覆盖核心。`original.html` 只追溯，不是基线来源。
- 本次检查所在目录不是 Git 仓库；实施者不得假定 Git、Node、npm、浏览器或任何包可用。以下命令在项目根目录执行；示例采用 PowerShell，其他平台按等价命令执行。安装、版本管理初始化及基线存储均须先获授权，不擅自 `git init`、提交或覆盖用户文件。
- 依赖关系：**T0 环境/恢复方案 → T1 确定工具、路径和生产隔离 → T2 适配与冻结基线、交互/状态/性能门禁 → T3 低耦合提取 → T4 上下文 → T5 场景逐个迁移 → T6 管线与类型 → T7 全量验收**。T2 所有阻塞项未通过，不进入 T3；T3–T6 每个小步均运行门禁并保留可恢复点。
- 每步的恢复点既包含源码、配置和锁文件，也包含对应测试；冻结基线单独只读保存，不随恢复点覆盖。Git 可用且经授权时记录 commit/工作树状态并只回退本步；否则在项目外建立带时间和清单的完整备份，验证可读、可还原。先记录已有用户改动，不用破坏性的全局 reset/clean。

## T0｜预检与可恢复起点

1. 只读检查：`node --version`、`npm --version`、`git --version`、`git rev-parse --is-inside-work-tree`；逐条记录命令不存在或失败，不因某一项失败跳过其他检查。Node 需满足 README 的 20.19+ 或 22.12+；确认磁盘空间、网络和浏览器安装权限。若缺工具，暂停并征得安装授权。
2. 有 Git 时记录 `git status --short`、`git rev-parse HEAD`；无 Git 时以项目外备份及文件 SHA-256 清单作为版本标识，例如 PowerShell 对备份文件用 `Get-FileHash -Algorithm SHA256`。排除 `node_modules`、`dist`，保留源文件、配置及锁文件；先用独立目录试恢复并比对清单。不要将备份放进项目测试扫描路径。
3. 授权后才运行 `npm ci`（使用现有 lockfile）；运行 `npm run typecheck`、`npm run build`，记录版本、退出码与输出，已有失败先处理为阻塞或明确记录，不作为重构引入的问题。构建会更新 `dist`，不影响冻结源码。
4. 验收：恢复演练通过、依赖版本可重现、原始源码标识和预检结果被记录。回退：恢复仅本步变更或从验证过的备份恢复，保留用户已有修改。

## T1｜先确定浏览器像素基线、路径与生产隔离

1. **提议，须批准**：新增精确锁定版本的 `@playwright/test`，使用与该版本绑定的 Chromium 二进制；在固定 OS/架构、Node、浏览器版本、viewport、DPR、颜色设置及字体环境运行。经批准后执行 `npm install -D --save-exact @playwright/test@<批准的版本>`、`npx playwright install chromium`，实际记录解析版本与浏览器 revision；若安装不可用则停在此处，不用随机本机浏览器替代。明确 package-lock 变化。
2. 约定路径并先检查冲突：`tests/browser/`（路径清单、交互、像素和隔离测试）、`tests/unit/`（状态）、`tests/support/`（控制器和比较器）、`playwright.config.ts`、`tsconfig.tests.json`（独立 strict 检查测试及配置）、`test-artifacts/`（实际图、差异图和报告，不入基线）、`baselines/small-worlds/<环境标识>/`（冻结参考）。实际依赖与命令写入 `package.json` 和测试 README；忽略临时产物，基线是否入库或外置须按体积与权限批准。
3. 提议新命令：`npm run test:unit`、`npm run test:browser`、`npm run test:baseline:collect`、`npm run test:perf`、`npm run typecheck:tests`；在实现中落实具体脚本与参数（如 `-- --manifest ...`），记录标准输出和退出码。单元测试工具单独选定并精确锁定，或使用获确认的 Node 内置测试运行方案；不要假定 TypeScript 能被 Node 直接执行。
4. 基线格式选无损原始 RGBA + 宽高、路径 ID 的 manifest；每份文件记录 SHA-256、字节数、原始源码版本/备份清单、生成命令与环境。容量先估算 `宽×高×4×样本数×环境数`，两次采集各自占空间；经批准选择版本化仓库或外部只读归档，保留校验信息、恢复方法和访问权限。原始数据不得被迁移后的运行覆盖。
5. 设计构建隔离：生产 `index.html` 始终进入正常 `src/main.ts`；另设仅测试服务使用的测试入口/HTML 和受控适配模块，且生产入口、生产依赖图均不导入它。禁止运行时 query/localStorage 开关把测试能力带进生产。构建后同时检查 `dist` 文件和 sourcemap（如开启）无测试入口、测试全局名称、测试控制代码；用生产 preview 浏览器断言测试全局不存在、测试入口 URL 不提供可执行测试页，且正常页面交互正常。结合构建依赖图检查，不能只靠字符串搜索声称隔离。
6. 验收：工具/版本、浏览器、两组视口/DPR、存储路径与容量、隔离策略和命令获得确认并写入测试文档；生产隔离检查有可执行的正反例。回退：移除本步新增的配置及经授权安装的依赖变更，恢复锁文件，不动基线。

## T2｜在原实现建立确定性基线与完整验证

### T2.1 最小适配层及路径清单

- 改造 `src/main.ts` 时仅抽出可注入的 RAF 调度/启动边界，测试入口在模块加载前安装可控时钟，保持首次帧、`lastFrameTime`、elapsed 上限 0.1、dirty、播放、拖动及 requestAnimationFrame 注册顺序。测试控制器只提供设置合法场景进度、推进一帧并等待绘制、读取完整 Canvas `getImageData(...).data` 和必要诊断状态；实际交互通过浏览器真实键盘和指针事件，不以直接 `renderScene` 代替应用。生产启动路径与之前一致。
- 在冻结的迁移前实现上同时验证适配前后生产页面交互和输出一致；适配层不能修改渲染、缓存、重置或调用次序。每个冷路径新页面/新模块实例，同一路径中按顺序逐帧推进，不重置中间状态。manifest 每条记录场景 ID/index、初始状态、完整事件和 RAF 时间戳、每个采样点 p、可由真实交互到达或仅测试入口直达、视口/DPR 及预期输出路径。
- 公共 p：`0, 0.039, 0.04, 0.041, 0.25, 0.5, 0.75, 0.969, 0.97, 0.971, 0.999`，五场景均覆盖；不假定 p=1 是正常播放终点。目标帧分别从冷启动、同场景前向 seek、后向 seek、其他场景进入；覆盖 A→B→A、日夜互切及运行时材质分配。不同路径各自对照自己的基线，先记录原有跨路径差异。
- 在 `tests/browser/paths.*` 逐场景扫描 `src/renderer.ts` 的 `build/update/post`，列出每个分支阈值、关键帧、动态对象发生/消失位置及阈值前/等于/后采样：例如 seasons 的 q=.49/.63/.72/.74，rise 的 q=.085/.17/.735/.86，harbour 的夜景和烟火，eruption 的 HOT_T 与喷发，liftoff 的点火/离地。按实际代码补齐而非仅用示例；q 转 p 用 `p=0.024+0.958*q`，liftoff 先核实源码 T 与 q、t 的关系再转换。记录无法由事件准确到达的点。检查清单须经另一人复核或用户确认。

### T2.2 采集、比较、状态和交互

1. 在 T1 固定环境及冻结版本中，独立运行采集命令两次，分别写新目录，逐样本比较宽、高和每个 RGBA 通道。比较器输出差异像素数、首批坐标、各通道值与无损差异图；固定环境要求零差异。先排查随机、时钟、DPR、浏览器或状态污染，不稳定样本阻塞验收；两次一致后按 manifest 校验并只读归档一份。测试运行时只读归档，结果放 `test-artifacts/`，不允许自动更新 baseline。
2. 状态测试使用仅测试构建注入的观测/小容量等价日志，验证同坐标多次覆盖逆序恢复 `grid/ap/va`；切场景旧日志不污染新场景；缓存场景只 build 一次；帧内 `fm` 分配后 `matCount/rampCount/staticTop` 和 `fmCache` 经切换保留；越界和容量满后忽略。另用真实 `JCAP=3000000` 验证边界，生产容量不变。避免只对淡出白屏做像素断言。
3. 浏览器真实事件：Space 切换并阻止默认；左右键首尾循环；Digit1–5 对应场景起点。播放/暂停两态分别测试有效区 pointerdown 捕获并立即 seek、拖动自动时间不推进但 pointermove 可改变时间、up/cancel 结束拖动并恢复原播放状态、区域外不拖动；验证坐标映射、两端钳制及 `lerp(0.024,0.982,position)*0.999`。减少动态效果时初始首场景第 4 秒且不自动推进，Space 可继续。
4. 采集 `state.bgMix` 大于和不大于 0.55 的实际帧，检查 html/body 计算背景分别为 `rgb(14, 18, 44)` 和白色（CSS 序列化规范化后比较）。至少两组 viewport/DPR，验证内部尺寸 `360/330 × max(1,floor(min(innerWidth/360,innerHeight/330)*DPR))`，CSS 尺寸除以 DPR；播放及暂停下 resize 后对照对应路径基线。
5. 每阶段命令：`npm run typecheck`、`npm run typecheck:tests`、`npm run build`、`npm run test:unit`、`npm run test:browser`，另执行生产隔离检查；具体脚本建立后写入测试 README。全部结果及 manifest 校验和归档。失败不更新基线，定位或回退当前小步。

### T2.3 性能基线及迁移前决策

- 与用户先确认测量边界（推荐完整 `draw`，不含 RAF 等待、自动化通信、截图与像素读取）、计时 API、固定操作路径、环境噪声控制和统计脚本；记录实际选择。各场景冷启动新页面重复 5 次；稳定帧和高动态帧各预热 30 帧再采 100 帧，记录中位数、P95、原始样本和环境。访问五场景后测内存，注明 API、可用性与限制；不可用标记未验证。
- **基线测得后、迁移前**与用户约定容忍区间和复测规则，记录批准依据；不预设百分比或固定阈值。无法达成或环境噪声不可控则停止迁移，不宣称性能通过。性能数据及像素冻结基线独立保存；原有缺陷需单独确认后才能变更基线。
- T2 验收：两次稳定、清单完备、交互与状态/隔离检查通过、性能协议获批、源码版本及可恢复备份已保存。回退适配时保留独立采集证据，不用未通过的采集进入后续阶段。

## T3｜低耦合拆分（依赖 T2）

按项单独实施并执行 T2.2 全门禁：
1. 从 `src/renderer.ts` 提出 `src/core/math.ts`、`noise.ts`、`constants.ts` 或 `tables.ts`；逐行保留 Float32/Uint 数组、初始化顺序、位运算和取整。新增严格类型、确定性查表单元测试。
2. 将 FONT、绘字/圆角框、滑块与 `upscale` 拆到 `src/ui/`；显式传入源像素、场景数和背景状态，原门面保留对 `main.ts` 的接口。不要改变 UI 绘制顺序、颜色、缩放或 hit test。
3. 每项验收：完整像素路径、事件、状态、生产隔离、typecheck/build 及约定性能检查通过；依赖图无环。回退仅该项，恢复其前一个检查点，不修改冻结基线。

## T4｜单实例上下文（依赖 T3）

- 新建 `src/renderer/context.ts`，梳理 `useScene/allocScene/saveCounts/ensureBuilt/undoDynFor` 及所有共享字段，列表标明所有者、首次分配、重置和保存时机；不复制大型 typed array。可暂留局部别名及 `saveCounts`，若改成直接字段访问必须删除对应旧标量真值。
- 每场景懒分配 grid/ap/va、材质、ramp、fmCache 和计数并缓存；共享 pal、像素/深度、shifted、帧状态、光照和唯一动态日志。日志属于最后绘制场景，切换先激活旧场景逆序撤销；`curAp/curVa` 只在首次 build 前后重置，build 后和每帧 post 后保存计数；保留 dynMode 及部分帧字段原有生命周期。
- 明确顺序：切换撤销旧日志 → ensureBuilt → 目标 undo → 按源码逐项 reset → update(q,p*10) → palette → voxels → post → saveCounts → shift/fade → upscale/UI → putImageData → 背景；`q=clamp((p-.024)/.958)`，`T=min(254,floor(q*255))`。不增加异常事务恢复保证，是否支持另议。
- 验收：T2 全门禁及状态测试逐项通过，确认无双重真值及无额外重置。回退上下文这一步及其依赖改动至检查点。

## T5｜场景契约与逐个迁移（依赖 T4）

1. 新建 `src/scenes/types.ts` 与组合根：对五个闭包逐个列出自由变量、读取/写入、调用位置、所有者及注入 API；以精确类型覆盖材料、体素、动态、光照、post，不能用宽泛 `any`。场景只依赖契约与注入能力，不反向导入门面/注册表；共享底层能力由组合根装配，避免环及隐式服务定位。
2. 依次迁移 `seasons`（原约 657–912 行）、`rise`（913–1187）、`harbour`（1188–1496）、`eruption`（1497–1799）、`liftoff`（1800–2091）到各自 `src/scenes/<id>.ts`；行号只是现状定位，每次按实际源码确认。保留每场景实例闭包、build/update/post、元数据与注册顺序。混合期明确单一注册源，迁出即删除旧定义，不能重复注册。
3. **每个大场景的操作检查单**：先用清单枚举所有自由变量和可变闭包；逐块搬迁函数体，不顺手重命名数学/改变循环；审查 diff 的常量、数组类型、取整及顺序；针对该场景补齐 T2 的事件阈值前/中/后、动态对象、后处理及材质分配路径；运行该场景冷启动、前后 seek、跨场景进出和 A→B→A 的逐帧像素对照及状态断言；随后运行五场景**完整**矩阵和交互、类型、构建、隔离、性能门禁。报告路径 ID、参考/实际 hash、差异坐标、构建次数及计数/cache 对照。
4. 若某块太大，先分离不改变执行顺序的私有 helper，在旧文件中验证后再移动；每小步保存恢复点，不在未验证的中间状态切换其他场景。所有场景通过后建立 `src/scenes/index.ts` 显式注册 `seasons, rise, harbour, eruption, liftoff`，测试索引、键盘和标题一一对应。
5. 入口避免 `renderer.ts` 与 `renderer/index.ts` 无扩展名解析歧义：过渡期 `main.ts` 继续唯一导入 `./renderer`；最终将实现移至明确的 `src/renderer/index.ts` 后，**同一步**更新 `main.ts` 为明确的 `./renderer/index` 并移除旧 `src/renderer.ts`，检查所有 import 无旧入口。门面维持既有导出形状。
6. 验收：每场景完整矩阵与旧路径零差异、构建一次且切回恢复、注册顺序不变、无环；回退当前场景或入口切换小步，不回退已验收场景、不覆盖基线。

## T6｜管线拆分与严格类型（依赖 T5）

- 逐项提取 `src/renderer/materials.ts`、`geometry.ts`、`voxel-renderer.ts`、`effects.ts`；先定义窄接口并由组合根注入动态写入/几何共同低层能力。每项核对调用顺序、typed-array 容量与索引、位运算、缓存及性能；热循环允许局部数组引用，不加大数组复制。
- 新模块全程 strict；逐段标注场景、材质选项、回调、颜色元组、缓冲和状态类型，最后移除遗留文件 `@ts-nocheck`。搜索 `@ts-nocheck`、`@ts-ignore` 和 `any`，逐项审查；渲染核心、场景和新模块不能用这些绕过类型。测试目录使用 `tsconfig.tests.json` 独立检查。
- 每次提取/类型化运行 T2 全门禁与协议性能测量；超区间先定位并复测，仍超则回退该小步或交用户决策，不通过更新基线掩盖。完成后确认依赖方向及生产唯一入口，清除过渡适配，但保留测试隔离能力。

## T7｜最终验收和交付（依赖 T6）

- 复核冻结基线校验和、环境、所有路径采样和完整 Canvas 逐通道零差异；交互、背景、尺寸、状态、生产隔离全部通过；对不可稳定样本保留阻塞状态，不降低标准。
